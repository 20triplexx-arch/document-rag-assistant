## 解决的问题

让不同学习者围绕 awesome-agentic-ai-zh 和 Hello-Agents 两本教材，学习概念、比较解释、定位章节。教材资料共享，账号及学习讨论各自保存；服务端核对记录所属用户，不能只靠网页隐藏别人的记录。当前不支持私人文档或笔记上传，避免把个人资料混入公共知识库。

首个使用场景：用户问“RAG 和长期记忆有什么区别？两本教材分别在哪里讲到？”，系统分别检索两本教材，解释区别，展示对应章节和原文片段；某一本缺少依据时单独说明，不能冒称已经比较两书。

## 第一版范围

1. 导入明确指定的 Markdown / TXT 文档，记录教材名称、章节、原始 URL、版本和文件哈希。第一批从两书记忆/RAG 相关章节开始，当前已扩充完整中文正文及配套说明，固定来源见 `sources-full.json`。
2. 按标题和段落切分，保留原文位置；长段落再分块。索引持久化，重复导入相同资料可以复用，资料变更要更新版本。
3. 支持按教材筛选和跨教材提问；先建立关键词检索基线，再接入既有语义检索能力。
4. 基于检索片段生成回答，展示教材、章节、原文片段和来源链接。模型选择的引用必须属于本次证据包。
5. 对资料不足、只能回答部分问题、两书观点或版本不一致分别说明。没有检索到依据不能推断教材没写过该内容。
6. 保存执行记录，包括语料版本、检索排名、最终证据、回答、停止原因、模型调用数、Token 和耗时。
7. 同时提供开发用命令行入口和本机 Web 界面。Web 问答必须登录，资料范围可选两本或单本，支持不调用模型的“只查原文”。用户已要求按多人标准建设，但先不部署上线。
8. 每位学习者拥有独立账号、会话和历史记录。讲解调用预算在数据库事务中预留，防止并发请求穿透个人或全局限额；同一请求编号重放不再次调用模型。

出题、错题本、学习进度、PDF 解析、录音、实时联网研究和公网部署属于后续扩展，各自需要单独实现与验收。

## 第一课：把数据流讲清楚

RAG 的意思是“先检索，再生成”。理解它时要分开两个过程：

```text
资料准备：教材原文 → 按章节切分 → 记录来源与版本 → 建立可重用索引

每次提问：问题 → 检索相关片段 → 读取原文证据 → 生成带引用回答
                                      ↓                 ↓
                               资料不足时说明       检查引用与证据
                                                        ↓
                                                   展示并记录结果
```

- 文档片段：从教材中切出的一个小段，必须能定位回原文。
- Embedding：用向量表示文本含义，供相似度检索使用；它不是答案。
- 索引：帮助查找资料的数据结构。来源版本是索引契约的一部分。
- 检索：挑选可能相关的片段。排名靠前不等于片段支持答案。
- 生成：模型根据片段组织解释。流畅不等于正确。
- 引用检查：程序能核对 ID、原文和位置；“结论是否被原文支持”还要另做内容评估。
- 学习记忆：记录学习进度或用户偏好，与存放教材知识的资料库承担不同职责。

理解检查：如果系统检索到了“RAG”段落，但段落没说明某产品的价格，它能否据此回答价格？如果答案引用了真实章节，但该章节没有支持结论，算不算正确？两种情况都不能当作成功回答。

## 组件与职责

| 组件 | 输入 | 输出与职责 |
| --- | --- | --- |
| 导入与切分 | 指定教材文件 | 带书名、章节、版本、位置的片段 |
| 索引与检索 | 文档片段、问题、教材筛选条件 | 排序后的候选片段，不读取评分标准 |
| 原文读取工具 | 片段 ID | 可定位、可核查的原文证据 |
| 学习辅导角色 | 问题和证据 | 通俗解释、跨教材比较或资料不足说明 |
| 证据审阅角色 | 问题、答案与证据 | 指出支持不足、缺失引用或需要修改的结论 |
| 运行控制 | 当前状态和调用预算 | 编排步骤、超时、明确停止，保存记录 |
| 评测与接口 | 固定题集或用户提问 | 逐案报告、可用入口 |

后续可比较学习辅导和证据审阅两个角色，明确交接内容和停止规则。先保留同题单角色基线，用效果、调用量和耗时决定审阅是否值得启用；程序检查与模型审阅分开报告。多用户账号不等于多智能体，当前每次讲解最多一次模型调用。

## 模型和环境方案

- 复用项目根目录 `.venv` 与根 `requirements.txt`；当前不安装依赖或创建新环境。

- 首批使用公开教材资料。调用 DeepSeek 时发送本次学习问题和检索到的公开教材正文，不发送账号密码、API 密钥或其他人的历史记录。当前每次问题独立检索，不利用聊天历史推理；不要输入敏感个人资料。
- 框架接入需核对本机 `hello-agents==0.1.1` 与教材示例版本差异，记录适配，不直接套用不兼容的原版接口。

## 评测计划

至少准备 5 道开发题和 3 道独立保留题。题目和答案依据在对应语料快照固定后建立、冻结并记录版本；目前尚未生成实际题集。保留题不用于调提示词，若根据其结果调参，应另建立新保留集。

题型覆盖单教材概念解释、原文定位、跨教材比较、资料不足和部分有依据的问题。技术异常另用离线测试覆盖，包括空文件、无索引、资料变更、模型超时、非法引用和调用预算耗尽。

每题分别评估：

- 检索是否找到预先标注的相关依据。
- 回答的主要结论是否正确，是否遗漏必要条件。
- 引用是否存在、原文和位置是否匹配、是否实际支持结论。
- 应回答的部分有没有回答，应说明资料不足的部分有没有说明。
- 调用数、Token、耗时和失败发生在哪一步。

评分依据只交给评测器，不能提供给检索器或回答模型。字符串匹配和引用格式正确不能冒称语义正确；人工逐条审阅与程序指标分开记录。验收规则在首次模型评测前确定，失败样例照实保存。

## 第二课：运行教材导入与检索基线（两章版历史记录）

这节先把真实教材变成能检索、能核对的片段；不生成模型答案。第一课中“引用存在不等于结论被支持”的理解检查，用户已回答“不算正确回答”。

### 四部分代码如何合作

1. `sources.json`：配置与来源契约，固定两本教材各一个章节的完整 Git 提交号。
2. `study_rag/core.py` 中的 Source、prepare_corpus、split_document：下载公开原文、计算文件哈希、按标题分节、按段落/行优先切分长节。每个片段保留正文、章节、字符范围和行号；跨片段保留最多 160 字重叠，同一片段不会跨越不同标题节。
3. 同文件中的 build_index、verified_chunks、search、read_evidence：持久保存片段，每次查询核对索引契约和原文；用中文双字与英文单词计算关键词相关排名；按片段 ID 读取原文。查询不接触评测答案。
4. `starter.py` 和 `test.py`：入口编排、交互菜单、运行报告、离线边界检查。每次运行报告均独立保存，成功/失败有明确退出码。

本节索引存储采用 SQLite，关键词排名采用 BM25 形式的基线。语义向量与 Chroma 将在后续接入；两种检索方法须在同一份语料和同一问题上比较。

### PyCharm 运行步骤

解释器继续使用根目录 `.venv`。直接打开并运行本目录文件：

1. 先运行 `test.py`，预期 `Ran 19 tests`、`OK`。使用合成测试资料，0 次网络请求、0 次模型调用，不证明真实问答质量。
2. 运行 `starter.py`，选 **1**。第一次最多下载两份公开原文，各一次 HTTPS 请求；已有语料完整时返回 `CORPUS_REUSED` 和 `INDEX_REUSED`，0 次下载。
3. 等进程退出，重新运行 `starter.py`，选 **2**。预期 `VERIFIED`，共 89 个片段：awesome 21 个、Hello 68 个。
4. 重新运行，选 **3**，输入 `RAG 和长期记忆有什么区别？`。查看每个候选的 `book`、`section`、`text`、`line_url`；`source_verified=true` 只表示原文已核对，`support_verified=false` 表示结论支持关系还没验证。
5. 复制某个 `chunk_id`，重新运行选 **4**，对照候选与原文是否一致。

源文件、语料版本和索引保存在本目录 `data/`，运行报告保存在 `output/`。已有索引或原文损坏时会停止，不能自动覆盖后宣称原版本仍有效。更新来源须通过 `--data-dir` 指定新目录。

### 本节总结与边界

现在具备的是“找回原文并确认没被改动”的能力。关键词排名分数不是可信度，也不能据“没匹配到关键词”宣布问题一定无答案。标题、表格、代码及 HTML 原样保留；长代码块、表格和单行仍可能被切断，图片内容和相对链接尚未解析。它们是后续资料处理与检索质量的改进项。

上述是第二课的历史基线记录；后续检索调整与真实调用记录见第三课。用户完成本节复现前，不将用户侧实操记为已完成。

## 第三课：多人边界与 DeepSeek 问答

从个人脚本变成多人应用，最重要的变化是把“身份”和“公共知识”分开。大家查询同一份教材，但不能靠猜测记录编号访问其他人的讨论。API 从登录会话识别用户，不接受浏览器提交 `user_id`。

```text
共享教材快照 → 来源核对 → 按书检索 → 本轮证据包
                                           ↓
账号会话 → 讨论所有权检查 → 事务预留调用额度 → DeepSeek
                                           ↓
                                  JSON / 引文出处检查
                                           ↓
                                  只写入该用户的讨论
```

“只查原文”跳过额度预留和模型调用；无检索匹配也不调用模型。引文出处检查只确认本轮编号与规范化正文片段匹配，不证明该片段支持整条解释。

### 分模块读代码

| 文件 | 当前职责 |
| --- | --- |
| `study_rag/core.py` | 原始教材、固定版本、切分、索引与原文校验；旧关键词基线仍可比较 |
| `study_rag/rag.py` | 每本书最多两个证据，概念模式屏蔽代码/图片/HTML、排除习题和参考文献；构建提示词、调用 DeepSeek、核对结构与引文出处 |
| `study_rag/store.py` | SQLite 账号、哈希密码、会话、用户所属记录，以及持久事务式预算和请求去重 |
| `study_rag/web.py` | FastAPI 接口、所有权检查、CSRF/来源检查、Cookie、安全响应头和模型编排 |
| `static/` | 登录/注册、教材选择、提问、原文模式和历史记录；展示文字不用 HTML 注入 |
| `serve.py` | 只绑定 `127.0.0.1` 的本机入口，默认端口 8765 |
| `test_multiuser.py` | 合成教材与假模型的隔离、预算、接口和引用边界测试，0 次真实模型调用 |

正文清洗保留原始片段与行号，只给模型及阅读面板展示清洗后的正文。引文核对忽略 HTML/Markdown 强调标签和多余空白，不修改词语、数字或标点。过滤代码有利于概念学习，但不适合代码问题；原始 CLI 检索仍保留代码。

### 在本机运行

从工作区根目录运行，继续使用已有 `.venv`。模型密钥已经存在，无需再次输入或贴到聊天中。

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s capstone/document-rag-assistant -p "test*.py" -v
.\.venv\Scripts\python.exe capstone/document-rag-assistant/serve.py
```

浏览器打开 `http://127.0.0.1:8765`。如该地址已打开，直接使用，不再启动第二个同端口进程。PyCharm 可直接运行 `serve.py`，解释器选根 `.venv`，不用修改密钥。当前依赖已可用，根 `requirements.txt` 补记实际版本，未安装新包。

用户复现顺序：创建自己的学习账号（密码 10～128 字符），先选择“只查原文”；提问并打开来源链接；退出后用另一个账号检查列表没有前一账号的记录；最后需要真实讲解时再选择“生成讲解”，这一步会消耗 DeepSeek 额度。不要为不同人共享同一账号。跨用户编号攻击已由自动测试覆盖，不需要用户手工修改接口。

默认保护：每人每天 20 次讲解、全站每天 100 次，全局最多 2 个生成请求，每人同时最多 1 个。按上海日期计数，每次请求先保守预留额度，失败也计入；这不是人民币余额上限。服务端可配置 `RAG_USER_DAILY_LIMIT`、`RAG_GLOBAL_DAILY_LIMIT`、`RAG_MAX_CONCURRENT`。单次最大输出 1400 Token、超时 45 秒、不自动重试。

`starter.py ask "问题"` 是维护者调试入口，不经过 Web 的账号和每日限额，不应作为公开服务入口。会独立保存调用日志，同样不回退到其他模型。

公共资料在 `data/`，账号与讨论在 `output/users.sqlite3`，均由项目 `.gitignore` 排除。密码用随机盐 PBKDF2-SHA256（600,000 次）保存，会话令牌只存哈希，浏览器用 HttpOnly / SameSite=Strict Cookie；退出撤销会话，登录有效期七天。数据库没有静态加密，应保护本机文件，勿上传用户库或整份 `output/`。本机 HTTP 开发默认不设置 Secure Cookie，未来 HTTPS 上线时必须启用并另做配置验收。
