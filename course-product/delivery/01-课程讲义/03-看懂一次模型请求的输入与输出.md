# 第03课 看懂一次模型请求的输入与输出

模块：认识 Agent | 建议用时：阅读25分钟 + 动手20分钟

## 学习目标

辨认消息角色、文本结果和工具请求；知道模型名称与密钥是两项独立配置。

## 中文讲解

应用调用模型时，传递的不是一个完整的“聊天窗口”，而是一组消息。system 定义任务规则，user 提供当前问题，assistant 保存模型过去的答复，tool 保存程序执行结果。模型是否看见过去的内容，取决于本次请求有没有把那些消息发送出去，不能依赖网页聊天里形成的直觉。

配套 common.py 用标准库 urllib 发送 JSON 请求。密钥只放在请求头，模型名称从 DEEPSEEK_MODEL 读取。当前示例名称 deepseek-flash 取自制作时的官方文档；你的账户可用型号和接口参数可能变化，所以脚本要求显式配置型号，并在配置说明中保留官方文档链接。

返回内容需要先检查再使用。正常文本在 assistant 消息的 content 中，工具请求在 tool_calls 中。空结果、HTTP 错误、输出因长度上限中断，都不应当被保存为一条“完成”的答案。common.py 会把这些情况转成可读错误，并且不自动重试，以免一次命令触发你没意识到的额外调用。

> 流程：messages → JSON 请求 → HTTP 响应 → 检查完整性 → 文本或工具请求

联网练习会发送输入和必要的历史或资料片段到模型服务，并可能产生费用。先使用课程中的虚构资料。工具项目最多四次模型请求，记忆与问答每轮最多一次；这只是程序的调用次数上限，不是固定金额上限。

## 示例与观察

这段代码只构造消息，不联网：
```python
messages = [
    {"role": "system", "content": "只回答 Python 学习问题。"},
    {"role": "user", "content": "字典怎么保存键值对？"},
]
assert messages[-1]["role"] == "user"
print(messages[-1]["content"])
```
联网配置步骤见“00-开始学习/配置与排错.md”，密钥不要放进截图或交付文件。

## 动手任务

阅读 common.py，找到请求头、模型字段、超时和 max_tokens。解释为何把 max_tokens 调小不等于降低输入长度。

## 参考答案

请求头含 Authorization；model 来自环境变量；超时为 60 秒；max_tokens 为 1200。输出预算限制生成长度，输入仍是 messages 的全部内容。完整响应检查会拒绝 finish_reason 为 length 的结果。

## 常见问题

问：设置了密钥还是报模型错误？答：确认 DEEPSEEK_MODEL 是当前账户可用名称，再检查官方说明。

问：HTTP 成功就代表答案正确吗？答：它只说明接口接受并返回了响应，事实正确、计算正确和证据支持要另行检查。
