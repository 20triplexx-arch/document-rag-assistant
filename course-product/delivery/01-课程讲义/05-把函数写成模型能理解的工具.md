# 第05课 把函数写成模型能理解的工具

模块：工具调用 | 建议用时：阅读25分钟 + 动手20分钟

## 学习目标

区分工具说明、参数结构和实际执行函数；理解注册表为何比函数名字更重要。

## 中文讲解

工具调用包含三个部分：说明告诉模型什么时候使用，参数结构描述输入，执行函数完成计算或访问外部系统。模型看到 calculate 的 JSON 描述，只能提出调用意图；它不会直接运行你的 Python 函数。程序必须把允许的工具名映射到明确函数，并检查输入。

配套工具接受 operation、a、b。operation 只允许四种基本运算，数字直接由程序计算。模型的责任是把“18 乘以 7”转换成结构化输入，程序的责任是得到 126。这个分工使结果可以独立验证，不必信任模型口算。

工具说明应写业务含义，而不是空泛地称其“强大”。比如“对两个数字做加减乘除”就能让模型判断是否适用。参数名要稳定；修改 a 为 first_number 时，schema、校验函数、测试和讲义示例要一起更新。

> 流程：工具说明 → 模型提出调用 → 注册表匹配 → 函数执行 → observation

不要根据模型输出动态导入模块或调用 eval。配套实现只分发给 calculate；未知工具返回结构化错误。上游案例可能使用其他实现方式，本课程独立练习采用明确的四种运算分支，让边界能直接读懂。

## 示例与观察

在练习目录运行：
```python
from tool_agent import execute_tool
result = execute_tool(
    "calculate",
    '{"operation":"multiply","a":18,"b":7}'
)
assert result == {"ok": True, "result": 126}
print(result)
```
模型调用字段与这个函数的输入最终都要映射到同一份参数契约。

## 动手任务

为摄氏度转华氏度设计一个工具说明和参数结构，写出真正计算公式，不需要联网。

## 参考答案

工具名可为 celsius_to_fahrenheit，输入只含 celsius，公式为 celsius * 9 / 5 + 32。说明应强调输入单位；测试 0 得 32、100 得 212。校验应拒绝字符串“100℃”，由调用方先转换明确单位。

## 常见问题

问：函数有 docstring 就足够了吗？答：框架可能从 docstring 推导结构，但运行时仍应校验实际参数。

问：工具结果必须是自然语言吗？答：字典更容易检查成功、失败和具体数据，模型也能读取结构化结果。
