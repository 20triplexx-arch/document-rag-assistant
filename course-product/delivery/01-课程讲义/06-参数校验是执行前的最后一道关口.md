# 第06课 参数校验是执行前的最后一道关口

模块：工具调用 | 建议用时：阅读25分钟 + 动手20分钟

## 学习目标

拒绝缺失、多余、类型错误和越界参数；区分结构校验与业务规则。

## 中文讲解

JSON 能成功解析，只说明它符合 JSON 语法，不说明业务可以执行。“a 是字符串”“b 为零”“多了一个危险字段”都是语法合法但契约不合法的例子。因此 execute_tool 先解析 JSON，calculate 再检查字段集合、运算名、类型、范围和除数。

Python 的 bool 是 int 的子类，只用 isinstance(value, int) 会把 True 当作数字 1。本练习明确拒绝布尔值，也拒绝非有限值和过大的数字。数值边界并不适合所有业务，但教学项目需要一个可以解释、可以测试的范围。

校验失败应让调用方看懂如何修复。错误返回包含 ok=False 和 error，不能在错误时把 result 默认为零。因为零是合法计算结果，假零会让后续步骤误以为执行成功。

> 流程：JSON 解析 → 字段集合 → 类型 → 数值边界 → 业务规则

工具 schema 中的 required 和 additionalProperties 有助于引导模型，但不能替代 Python 侧校验。即使某个模型支持更严格的输出约束，你仍需要防止手工调用、版本变化和异常响应绕过说明。

## 示例与观察

执行四种失败输入：
```python
from tool_agent import calculate, execute_tool
print(calculate({"operation":"divide","a":6,"b":0}))
print(calculate({"operation":"add","a":True,"b":2}))
print(calculate({"operation":"add","a":"3","b":2}))
print(execute_tool("calculate", "invalid json"))
```
每一种都应该返回错误，而不是把输入悄悄改成另一个计算。

## 动手任务

增加三个测试：缺字段、多字段、绝对值超过 10^12。说明为什么不能直接删除多余字段后继续执行。

## 参考答案

缺字段无法确定意图；多字段表示调用契约发生变化，应拒绝并让调用方修正；超界可能造成资源或数值问题。悄悄删除多余字段会隐藏版本不一致，也可能改变任务含义。

## 常见问题

问：为什么不自动把“3”转成 3？答：教学契约选择严格类型，转换责任清楚；若业务允许转换，应定义规则并单独测试。

问：所有错误都抛异常好吗？答：可预期的业务错误适合结构化返回；接口或配置无法继续时再用 CourseError 终止。
