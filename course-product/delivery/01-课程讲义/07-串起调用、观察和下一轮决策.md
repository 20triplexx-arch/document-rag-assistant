# 第07课 串起调用、观察和下一轮决策

模块：工具调用 | 建议用时：阅读25分钟 + 动手20分钟

## 学习目标

阅读一条完整工具消息链；正确匹配 tool_call_id；控制模型轮次。

## 中文讲解

联网工具循环每轮发送当前消息列表。模型若返回文本，算术助手先检查是否真的执行过工具，没有调用记录就拒绝把文本当作完成；若返回 tool_calls，程序先保存这条 assistant 消息，再逐个执行工具，并把 tool 消息追加到历史。下一轮模型同时看到“我请求了什么”和“程序返回了什么”。

tool_call_id 是结果与请求之间的连接。一次模型响应可以提出多个调用，结果必须对应各自 ID；不能把所有结果合成一条没有 ID 的 user 消息。配套程序拒绝缺失和重复 ID，避免结果被错配。

“18×7，再加9”可以分两步完成：先得到 126，再把 126 与 9 相加得到 135。模型也可能先自行组织成其他合理调用路径，因此联网时不要要求固定调用次数；验收重点是执行结果和最终答案一致，并没有绕过工具。

> 流程：assistant.tool_calls → calculate → tool 消息 → 再次请求 → 最终文本

程序限制最多四次模型请求和八次工具调用。达到限制就停止并显示错误，不把最后一条工具结果冒充完整答案。上限是实验预算的一部分；生产系统还需要取消、耗时和重复调用管理。

## 示例与观察

离线计算第二步：
```powershell
python tool_agent.py --operation multiply --a 18 --b 7
python tool_agent.py --operation add --a 126 --b 9
```
可选联网：
```powershell
python tool_agent.py --online --question "18乘7之后再加9"
```
联网响应中 trace 展示工具结果，不打印密钥。

## 动手任务

画出两次计算所需的消息角色顺序。然后说明模型连续提出工具请求却没有最终文本时如何处理。

## 参考答案

角色顺序为 system、user、assistant(tool_calls)、tool、assistant(tool_calls)、tool、assistant(文本)。若始终不结束，轮次上限触发 CourseError。不能继续无限循环，也不能把一次中间结果标成最终完成。

## 常见问题

问：每次工具调用都需要模型吗？答：执行函数本身不需要；模型负责在循环中选择何时调用。

问：离线模式会自动理解中文运算问题吗？答：不会，它读取命令行指定的 operation、a、b，输出会注明模式。
