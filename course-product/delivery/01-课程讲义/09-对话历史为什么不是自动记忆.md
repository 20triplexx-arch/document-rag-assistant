# 第09课 对话历史为什么不是自动记忆

模块：会话与记忆 | 建议用时：阅读25分钟 + 动手20分钟

## 学习目标

区分进程内列表、持久化记录和本次模型上下文；解释重启与记忆的关系。

## 中文讲解

messages 列表只存在于当前 Python 进程里，退出后通常消失。把它存进数据库，可以在下一次运行恢复记录；但模型不会自动读取数据库。应用仍需要查询记录、选择要发送的内容，再构造 messages。这三个位置不能混为一谈。

课程的离线记忆演示只回放上一次用户输入，验证数据库是否跨进程保留。它没有语义理解，也没有从历史里提炼长期偏好。联网模式会把近期完整对话传给模型，让你观察“发送的上下文”与“数据库里全部历史”之间的差别。

一条对话最好保存角色和文本，而不是只保存一个拼接长字符串。角色明确以后，恢复时才能区分用户请求与助手答复，也容易检查重复或缺失。会话 ID 决定查询哪组记录；本地练习的 session 只是分组键，不是登录身份或权限系统。

> 流程：本次输入 → 读取会话记录 → 选取上下文 → 得到答复 → 保存记录

完成本课后，你应该能指出一次“模型忘记”的原因属于哪个层次：没有保存、没有恢复、没有发送，还是模型收到后没有正确使用。先检查前面三项，再评价模型能力。

## 示例与观察

用两个独立命令验证：
```powershell
python memory_chat.py --session alice --message "我想做文档问答"
python memory_chat.py --session alice --message "我上次说了什么？"
python memory_chat.py --session bob --message "开始学习"
```
alice 的第二次运行回放前一句；bob 不应该读到 alice 的记录。

## 动手任务

画三个盒子：进程列表、SQLite、模型输入。分别写出重启后保留什么，以及哪一步决定模型能看见什么。

## 参考答案

进程列表退出后消失；SQLite 文件保留历史；模型输入由程序每次重建。数据库保存了事实，不意味着该事实必然出现在本轮请求，也不意味着模型永远记得它。

## 常见问题

问：session 不同就等于账号隔离吗？答：本项目只有分组过滤，没有认证。持有数据库文件的人可以读取所有内容。

问：离线回放能证明长期记忆了吗？答：它证明保存和恢复，不能证明语义检索、偏好学习或记忆准确性。
