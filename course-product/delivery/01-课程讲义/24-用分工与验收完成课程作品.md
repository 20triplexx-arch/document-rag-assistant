# 第24课 用分工与验收完成课程作品

模块：MCP 与协作 | 建议用时：阅读25分钟 + 动手20分钟

## 学习目标

给多 Agent 设计清楚职责；控制共享状态；用成果与失败样本展示学习结果。

## 中文讲解

多 Agent 的价值来自职责与信息分工。一个负责找资料，一个负责阅读，一个负责整理，可以让阶段更清楚；但如果每个角色都重复搜索、重复总结，成本增加而质量未必提高。先说明单 Agent 哪里受限，再决定拆分。

分工还需要交付接口。研究角色输出来源和事实，审核角色检查冲突与缺失，整理角色依据已确认事实写报告。角色名称本身不保证行为，交付字段、来源要求和验收条件才决定能否组合。

共享状态应明确谁能写什么。两个 Agent 同时覆盖同一个 itinerary 字段，后执行的可能抹掉前面的约束。旅行案例中的团队协调器与成员组织展示了一种结构，但预算和时间是否满足，仍需要确定性检查与人工复核。

> 流程：任务拆分 → 角色交付 → 来源检查 → 合并结果 → 约束验收

结课时整理三个基础作品，每个附一条成功输入、一条失败输入、执行方式和局限。再任选一个上游案例，写一页架构说明和一个你会改进的问题。作品应展示你能解释系统，而不是把模型截图当作全部成果。

## 动手任务

用三个练习制作一份作品说明，并给多 Agent 研究团队写出“找、读、审、写”的交付字段。

## 参考答案

作品说明包含问题、数据流、运行命令、成功结果、失败边界和改进方向。研究字段至少有标题、URL、时间、原文依据；审核字段有支持状态与冲突；整理阶段不得把未确认内容写成事实。

## 常见问题

问：做完就能当生产项目卖给企业吗？答：课程是教学入门，还需权限、部署、监控、评测和真实数据验证。

问：如何判断学习完成？答：能独立运行、解释每个阶段、复现失败并核对证据，比背诵术语更有用。
