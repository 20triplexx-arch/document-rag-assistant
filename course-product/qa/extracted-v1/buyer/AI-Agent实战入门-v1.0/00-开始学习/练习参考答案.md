# 24课练习参考答案

建议先完成任务，再核对这里的答案。

## 第01课 用三个小作品建立学习路线

任务：为三个作品各写一句验收条件，必须包含输入、预期行为和检查方法。然后写出你最想替换的真实学习任务。

参考答案：示例：输入 18×7，calculate 返回 126，并能在 observation 中查看；连续运行两次记忆程序，第二次输出包含第一次输入；问报销材料，sources 指向报销规则中的材料段落。真实任务可以是“从自己的产品说明里查退换条件”，先用虚构或公开资料测试。

## 第02课 把环境问题与业务问题分开

任务：建立环境并运行计算示例。记录解释器路径，然后从另一个目录运行 document_qa.py，解释为什么默认示例资料仍能被找到。

参考答案：虚拟环境解释器在 .venv 下。文档目录使用 Path(__file__).resolve().parent 定位，取的是脚本所在目录，不是终端当前位置。memory_chat 的相对 --db 路径则取决于当前位置；需要固定位置时显式传入 --db。

## 第03课 看懂一次模型请求的输入与输出

任务：阅读 common.py，找到请求头、模型字段、超时和 max_tokens。解释为何把 max_tokens 调小不等于降低输入长度。

参考答案：请求头含 Authorization；model 来自环境变量；超时为 60 秒；max_tokens 为 1200。输出预算限制生成长度，输入仍是 messages 的全部内容。完整响应检查会拒绝 finish_reason 为 length 的结果。

## 第04课 选择工作流，还是让模型选择行动

任务：分别给“固定格式报销检查”和“根据问题决定查资料或计算”选择控制方式，并写出一个停止条件。

参考答案：报销检查用固定规则；问题分流可用模型提出工具选择。后者至少设置最大轮次、允许工具列表和成功输出检查。若只有两种明确关键词，也可先写规则分流，再评估是否需要模型。

## 第05课 把函数写成模型能理解的工具

任务：为摄氏度转华氏度设计一个工具说明和参数结构，写出真正计算公式，不需要联网。

参考答案：工具名可为 celsius_to_fahrenheit，输入只含 celsius，公式为 celsius * 9 / 5 + 32。说明应强调输入单位；测试 0 得 32、100 得 212。校验应拒绝字符串“100℃”，由调用方先转换明确单位。

## 第06课 参数校验是执行前的最后一道关口

任务：增加三个测试：缺字段、多字段、绝对值超过 10^12。说明为什么不能直接删除多余字段后继续执行。

参考答案：缺字段无法确定意图；多字段表示调用契约发生变化，应拒绝并让调用方修正；超界可能造成资源或数值问题。悄悄删除多余字段会隐藏版本不一致，也可能改变任务含义。

## 第07课 串起调用、观察和下一轮决策

任务：画出两次计算所需的消息角色顺序。然后说明模型连续提出工具请求却没有最终文本时如何处理。

参考答案：角色顺序为 system、user、assistant(tool_calls)、tool、assistant(tool_calls)、tool、assistant(文本)。若始终不结束，轮次上限触发 CourseError。不能继续无限循环，也不能把一次中间结果标成最终完成。

## 第08课 让失败有分类，也有恢复办法

任务：为“工具参数错误”“HTTP 401”“HTTP 超时”各写一个恢复动作。再写一个不能盲目重试的工具例子。

参考答案：参数错误修正字段后重提；401 检查密钥；超时检查任务是否执行及外部状态后再决定。创建订单、支付或发信都可能产生重复副作用，需要操作标识与状态查询。

## 第09课 对话历史为什么不是自动记忆

任务：画三个盒子：进程列表、SQLite、模型输入。分别写出重启后保留什么，以及哪一步决定模型能看见什么。

参考答案：进程列表退出后消失；SQLite 文件保留历史；模型输入由程序每次重建。数据库保存了事实，不意味着该事实必然出现在本轮请求，也不意味着模型永远记得它。

## 第10课 用 SQLite 保存一轮完整对话

任务：输入一句包含单引号的文本，确认能正常保存。随后切换 session，验证记录没有串组。

参考答案：例如输入“我在读 Python's tutorial”。SQL 参数化使引号作为普通文本保存。新的 session 查询为空或只包含该组自己的对话，不能出现旧会话内容。

## 第11课 把有限上下文当成预算来管理

任务：设计一个五轮对话，把重要约束放在第一轮。裁剪到最近两轮后，解释模型为什么可能不知道约束。

参考答案：约束被裁剪后没有出现在本次 messages，模型没有可靠来源。可将经过确认的任务约束放入独立状态，每轮显式发送；不要要求模型凭空记住未传入的历史。

## 第12课 给长期记忆定义范围与失效规则

任务：给“学习方向”“本次旅行预算”“模型猜测的用户职业”各选择保存策略。

参考答案：学习方向经用户确认后可长期保存并允许修改；预算限制在本次任务；猜测的职业不应当变成确认事实。保存时附来源并为用户保留修正方式。

## 第13课 切分文档时保留事实和位置

任务：把“私人聚餐不报销”写成紧挨费用规则的例外，比较分在同一段和分在相隔很远的段落时的检索结果。

参考答案：例外与规则在同一段时更容易一起检索。远距离切分可能只召回规则而遗漏例外；可以改善文档结构、扩大相邻片段或用结构化条件，不能只依赖模型补出缺失内容。

## 第14课 分清关键词检索和向量检索

任务：为一个产品说明文档写三道精确术语题、三道同义题和两道无答案题，保存预期证据位置。

参考答案：例：精确题“保修期限是多少”，同义题“坏了多久内能免费修”，无答案题“竞争品牌保修多久”。预期证据应指向真实文档；无答案题应注明没有对应证据，而不是给一个编造的位置。

## 第15课 把资料放进回答流程，而不是放进承诺

任务：问“报销什么时候到账”，检查原文是否提供到账日。写出合适的回答边界。

参考答案：原文只说 20 日前提交，超过该日进入下月审核，没有到账日期。合适回答说明已知提交与审核规则，并明确无法依据现有资料确定到账时间。

## 第16课 核对引用，也核对结论

任务：给“私人聚餐可报销，只要有发票”这句话找支持，并指出错误部分。

参考答案：教学原文明确私人聚餐不在报销范围，发票不能改变费用范围。这句话应判为与原文冲突，不能因为引用了报销材料段落就接受。

## 第17课 融合两路检索时先统一比较方式

任务：为编号查询与同义查询各造一份两路排名，运行 fuse，解释结果。

参考答案：编号题的关键词第一名可能最可靠；同义题向量第一名可能更有帮助。融合只是排序方法，仍须检查证据是否回答问题。两路同时排前不代表来源独立或结论正确。

## 第18课 重排解决的是候选顺序

任务：从自己的问题中取五个候选，先人工排序，再写出每条排序理由。

参考答案：理由应对应问题要求，例如“包含时间条件与后续处理”，不要只写“分数高”。如果五条都不含答案，结论应是召回失败，不能硬选一条当正确证据。

## 第19课 检索纠错要有触发条件

任务：给“报销材料”与“到账日期”各设计一个相关性检查条件，以及资料不足时的动作。

参考答案：材料题需要召回列明材料的段落；到账题需要明确到账日期或规则。若只有审核信息，到账题应说明缺失。允许公开检索也不能拿别家公司政策当成本公司的答案。

## 第20课 按数据流诊断故障，而不是盲改提示词

任务：建立八题回归表，并挑一题故意修改文档，验证记录能发现行为变化。

参考答案：可用材料、截止时间、超期、费用范围、私人聚餐、PDF支持、同义材料、到账日期八题。改动截止时间后应更新预期；若结果仍指向旧内容，检查缓存或索引版本。

## 第21课 理解 MCP 的主机、客户端与服务端

任务：给“查询资料库”和“创建日历事件”各写出 Server 应提供的能力，说明哪个属于有副作用的工具。

参考答案：查询资料库是只读工具或资源读取；创建事件是写入工具，需要明确日期、时区、对象和授权。MCP 让连接统一，不会自动消除写入风险。

## 第22课 浏览器行动需要观察与结果核对

任务：为“点击下一页后页码未变”和“页面弹出登录框”各写出合理下一步。

参考答案：页码未变先重新观察是否按钮禁用、加载失败或命中错误控件；登录框先判断任务是否确实需要登录及是否具备授权，不绕过访问控制。不能把动作尝试写成任务完成。

## 第23课 多服务协作先确定数据与权限边界

任务：设计“读取问题列表并生成待办草稿”的两阶段流程，列出每阶段所需权限。

参考答案：第一阶段只读仓库问题，第二阶段在本机生成草稿，不需要日历写权限。真正创建事件是第三阶段，需校验字段并取得对应授权。不要为只读任务一开始就授予全面管理权限。

## 第24课 用分工与验收完成课程作品

任务：用三个练习制作一份作品说明，并给多 Agent 研究团队写出“找、读、审、写”的交付字段。

参考答案：作品说明包含问题、数据流、运行命令、成功结果、失败边界和改进方向。研究字段至少有标题、URL、时间、原文依据；审核字段有支持状态与冲突；整理阶段不得把未确认内容写成事实。
