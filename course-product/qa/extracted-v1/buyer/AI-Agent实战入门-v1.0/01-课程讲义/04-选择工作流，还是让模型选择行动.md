# 第04课 选择工作流，还是让模型选择行动

模块：认识 Agent | 建议用时：阅读25分钟 + 动手20分钟

## 学习目标

用任务稳定性判断控制方式；明确 Agent 的循环与停止条件。

## 中文讲解

工作流由程序预先决定步骤。例如“读取文档、切分、检索、展示摘录”，下一步始终固定。模型可以参与其中的某个节点，但不一定决定路径。Agent 的典型差别是：模型根据当前任务和工具结果，选择是否执行下一次行动。课程的文档问答基础版是检索工作流，联网计算助手包含由模型选择工具的循环。

先把任务中的稳定规则写出来。如果所有报销申请都必须包含三项材料，完整性检查适合普通 Python 逻辑。只有问题表达变化很大、需要动态选择工具时，再让模型参与决策。固定规则也更容易测试，不需要为“缺一个字段”付费调用模型。

Agent 循环必须有终点。模型输出文本可以视作一条结束候选，但还要检查内容是否完整。次数、超时和允许的工具集合应由程序控制；把“请别无限调用”写进提示词不能替代这些控制。配套工具助手只允许 calculate，并限制模型轮次和工具次数。

> 流程：固定工作流由程序选路；Agent 循环由模型提议、程序约束

不要用“越自主越高级”评价方案。一次任务只有一个确定计算时，直接调用函数更简洁。学习 Agent 的意义是理解动态路径如何被管理，能在必要的地方使用它，并知道在哪里退回确定性的代码。

## 示例与观察

固定流程示例：
```python
def expense_check(form):
    required = {"invoice", "details", "approval"}
    missing = required - set(form)
    return {"ok": not missing, "missing": sorted(missing)}
print(expense_check({"invoice": "a", "details": "b"}))
```
这里无需模型，结果稳定为缺少 approval。

## 动手任务

分别给“固定格式报销检查”和“根据问题决定查资料或计算”选择控制方式，并写出一个停止条件。

## 参考答案

报销检查用固定规则；问题分流可用模型提出工具选择。后者至少设置最大轮次、允许工具列表和成功输出检查。若只有两种明确关键词，也可先写规则分流，再评估是否需要模型。

## 常见问题

问：用了 LangGraph 就一定是 Agent 吗？答：框架名称不能决定控制方式，要看路径由谁选择。

问：多步骤就是 Agent 吗？答：按固定顺序执行十个节点仍然可以是工作流，关键在决策权。
