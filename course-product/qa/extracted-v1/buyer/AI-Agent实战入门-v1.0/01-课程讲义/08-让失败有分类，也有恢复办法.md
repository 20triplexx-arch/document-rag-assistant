# 第08课 让失败有分类，也有恢复办法

模块：工具调用 | 建议用时：阅读25分钟 + 动手20分钟

## 学习目标

区分参数错误、工具错误和模型服务错误；避免无限重试和重复写入。

## 中文讲解

失败至少有三层。参数错误发生在执行之前，例如缺字段；工具业务错误发生在函数内部，例如除零；接口错误发生在模型请求，例如认证失败或超时。恢复方式不同，不能都归结为“再试一次”。

对于参数错误，模型可以读取 observation 并改正参数，但仍然受轮次上限约束。对于认证或余额问题，重复同一请求通常没有帮助，应先修改配置。对于超时，外部系统可能已经完成了操作，只是结果没有返回；如果工具会创建订单，直接重试可能重复执行。

教学计算是纯函数，相同输入总得到相同结果，没有外部写入，所以容易试验。把它换成发送邮件或提交表单时，要先设计请求标识、执行状态和确认边界。不要从“计算可以重试”推导“任何行动都可以重试”。

> 流程：失败分类 → 是否已执行 → 是否可重复 → 修正或停止

日志记录任务 ID、工具名、耗时和错误类别足以支撑初步排错。密钥不进入日志；涉及私有输入时也应限制原文记录。课程练习打印的是虚构任务和结构化结果，供你观察数据流。

## 示例与观察

构造未知工具和除零错误：
```python
from tool_agent import execute_tool
print(execute_tool("send_email", "{}"))
print(execute_tool(
    "calculate", '{"operation":"divide","a":9,"b":0}'
))
```
前者未执行任何动作，后者识别到合法工具但业务条件不满足。

## 动手任务

为“工具参数错误”“HTTP 401”“HTTP 超时”各写一个恢复动作。再写一个不能盲目重试的工具例子。

## 参考答案

参数错误修正字段后重提；401 检查密钥；超时检查任务是否执行及外部状态后再决定。创建订单、支付或发信都可能产生重复副作用，需要操作标识与状态查询。

## 常见问题

问：自动重试总能提高成功率吗？答：不一定，配置错误不会靠重试解决，写入工具还可能重复动作。

问：课程计算函数为什么不做复杂重试？答：它在本机立即执行，主要失败可直接分类，不需要引入额外调度机制。
