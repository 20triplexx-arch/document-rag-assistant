# 第10课 用 SQLite 保存一轮完整对话

模块：会话与记忆 | 建议用时：阅读25分钟 + 动手20分钟

## 学习目标

理解参数化 SQL、稳定排序和事务；验证失败请求不会留下半轮记录。

## 中文讲解

SQLite 把数据保存在本地文件，适合单人学习和小规模原型。配套 messages 表包含递增 id、session、role、content。id 用于确定消息顺序，session 用于过滤，role 用于恢复消息角色。不要依赖数据库返回的自然顺序，查询里显式写 ORDER BY id。

SQL 使用问号参数占位，再把值作为元组传入。这样输入中的引号会作为数据处理，不会改变 SQL 结构。直接把用户内容拼进 SQL 字符串容易造成语法问题和注入风险。学习时即使只是虚构输入，也应养成参数化习惯。

一轮对话在获得完整答复后一起保存两行：user 与 assistant。数据库事务使这两行作为一个整体提交。若联网失败，程序不保存这轮输入，避免未来恢复出一个没有回答的半轮记录。课程选择这个简洁规则，生产系统可另设明确的 pending 状态。

> 流程：生成成功 → 事务开始 → 写入用户与助手 → 提交 → 按 id 恢复

查看文件大小不是验证记录完整性的好办法。用 --history 查询角色、文本和顺序，再用独立进程运行确认持久化。数据库文件属于你的运行数据，不要和空白课程源码一起发给别人。

## 示例与观察

查看当前会话：
```powershell
python memory_chat.py --session alice --history
```
参数化查询的核心形式：
```python
rows = conn.execute(
    "SELECT role, content FROM messages WHERE session = ? ORDER BY id",
    (session,)
).fetchall()
```
该片段里的 conn 与 session 来自 memory_chat.py 的 history 函数。

## 动手任务

输入一句包含单引号的文本，确认能正常保存。随后切换 session，验证记录没有串组。

## 参考答案

例如输入“我在读 Python's tutorial”。SQL 参数化使引号作为普通文本保存。新的 session 查询为空或只包含该组自己的对话，不能出现旧会话内容。

## 常见问题

问：两个进程同时写会怎样？答：SQLite 会管理写锁，但本练习没有多用户服务和复杂重试，验收范围是单人串行运行。

问：删除终端记录会删除数据库吗？答：不会，文件仍在 --db 指定的位置。
