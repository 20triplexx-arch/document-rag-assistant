# 第11课 把有限上下文当成预算来管理

模块：会话与记忆 | 建议用时：阅读25分钟 + 动手20分钟

## 学习目标

选择近期完整轮次；理解字符预算与 token 预算的区别；说明被截掉的信息。

## 中文讲解

把所有历史每次都发给模型，会让请求越来越长，费用和延迟也可能增加。模型的输入容量有限，即使接口接受长上下文，早期信息也未必被稳定使用。先明确哪些内容值得保留，比盲目增加窗口更有用。

配套 recent_context 从最近的 user/assistant 配对向前选，最多六条消息，并设置 6000 字符的近似预算。它不会把一轮对话从中间截断，也不会把单个 assistant 消息悬空放在最前面。当前用户问题另外追加，数据库中的旧历史并未删除。

字符不是 token：中文、英文、数字和符号的分词不同。这里用字符预算是为了把控制机制讲清楚，不承诺它对应某个精确接口预算。需要严格费用管理时，应使用当前模型的计量办法并读取接口 usage。

> 流程：全部历史 → 最近完整轮次 → 预算裁剪 → 当前问题 → 模型输入

摘要是另一种压缩方式，但会引入新错误。摘要里漏掉“只用公开资料”这样的约束，后续模型就无法恢复。保存摘要时应保留原始历史和摘要版本，区分事实、用户要求和助手建议。课程基础项目暂不自动摘要，避免把生成误差藏进记忆。

## 示例与观察

检查裁剪结果：
```python
from memory_chat import recent_context
history = []
for i in range(5):
    history += [{"role":"user","content":f"问题{i}"},
                {"role":"assistant","content":f"答复{i}"}]
selected = recent_context(history, limit=4)
assert len(selected) == 4
assert selected[0]["content"] == "问题3"
```
只保留最后两轮，旧记录仍可从数据库查询。

## 动手任务

设计一个五轮对话，把重要约束放在第一轮。裁剪到最近两轮后，解释模型为什么可能不知道约束。

## 参考答案

约束被裁剪后没有出现在本次 messages，模型没有可靠来源。可将经过确认的任务约束放入独立状态，每轮显式发送；不要要求模型凭空记住未传入的历史。

## 常见问题

问：最多六条消息是六轮吗？答：不是，user 与 assistant 各算一条，通常是三轮。

问：裁剪会删除数据库里的历史吗？答：不会，它只影响本轮模型输入。
