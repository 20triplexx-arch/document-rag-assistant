# 第12课 给长期记忆定义范围与失效规则

模块：会话与记忆 | 建议用时：阅读25分钟 + 动手20分钟

## 学习目标

区分历史记录、任务状态与长期事实；识别过期、冲突和跨会话泄漏。

## 中文讲解

长期记忆不是把全部聊天永久堆在一起。历史记录保存发生过的对话，任务状态保存正在做什么，长期事实保存可能在未来重复使用的信息，例如用户确认的学习目标。三者在来源、保存期限和更新方式上都不同。

一条长期事实至少应知道内容、来源、确认时间和适用范围。“预算是1000元”可能只适用于某次旅行；如果直接变成永久偏好，下次任务会沿用错误约束。新旧信息冲突时，需要明确哪个更近、哪个被用户确认，而不是把两条都拼进提示词。

检索到记忆也不代表必须使用。先检查任务是否相关、信息是否仍有效、会话或用户边界是否允许。课程的 session 过滤展示了最基本的分组思想，但不包含加密、认证或权限判断。

> 流程：候选事实 → 明确来源 → 确认范围 → 保存 → 到期或更新

可从小表格开始设计，不必立刻安装复杂记忆框架。对学习目标设置“用户主动更改时更新”，对当次预算设置“任务结束失效”。这种明确规则让程序更容易解释，也能避免无关的旧事实干扰新任务。

## 示例与观察

教学事实对象：
```python
fact = {
    "content": "本次旅行预算1000元",
    "source": "用户本次输入",
    "scope": "trip-001",
    "status": "confirmed",
}
print(fact["scope"])
```
这是设计示例，配套 SQLite 项目实际只保存对话消息。

## 动手任务

给“学习方向”“本次旅行预算”“模型猜测的用户职业”各选择保存策略。

## 参考答案

学习方向经用户确认后可长期保存并允许修改；预算限制在本次任务；猜测的职业不应当变成确认事实。保存时附来源并为用户保留修正方式。

## 常见问题

问：RAG 和长期记忆一样吗？答：二者都可能涉及检索，但 RAG 常查外部知识，长期记忆还涉及个人事实的更新、范围和生命周期。

问：本包有自动学习用户偏好吗？答：没有，基础项目验证历史保存、恢复和上下文选择。
