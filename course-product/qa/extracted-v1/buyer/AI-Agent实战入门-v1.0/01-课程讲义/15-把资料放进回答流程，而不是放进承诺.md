# 第15课 把资料放进回答流程，而不是放进承诺

模块：文档问答 | 建议用时：阅读25分钟 + 动手20分钟

## 学习目标

构建检索增强生成数据流；区分离线摘录与联网回答；处理无结果。

## 中文讲解

RAG 的应用流程可以拆成检索和生成。检索找到候选片段，生成把问题与片段组织成答复。两个阶段都可能失败：没找到相关资料时，模型再会表达也没有证据；资料找对了时，模型仍可能忽略例外或补出不存在的结论。

配套 document_qa 默认离线输出原文摘录，sources 提供位置。加 --online 后，才把最多三个候选片段与问题发送给 DeepSeek。这个区分让你先验证检索，再验证生成，不把两类问题混在一起。

没有检索结果时，程序返回说明并且不请求模型。有结果也不一定足够回答问题：例如文档给了提交日期，却没有到账日期。联网提示要求只据资料作答，但仍要人工检查是否把“进入审核”写成“钱已到账”。

> 流程：问题 → 候选片段 → 来源编号 → 模型答复 → 回查证据

检索资料是数据，不应当变成新的程序指令。文档里出现“忽略系统要求”时，也应被视为原文内容。提示词提供基础约束，但完整系统还需要隔离工具权限、限制数据访问和处理恶意内容。

## 示例与观察

默认离线：
```powershell
python document_qa.py "每月几号前提交报销？"
```
可选联网：
```powershell
python document_qa.py "20日以后提交会怎样？" --online
```
联网会传输选中的文档片段；不要使用未经允许的私有资料。

## 动手任务

问“报销什么时候到账”，检查原文是否提供到账日。写出合适的回答边界。

## 参考答案

原文只说 20 日前提交，超过该日进入下月审核，没有到账日期。合适回答说明已知提交与审核规则，并明确无法依据现有资料确定到账时间。

## 常见问题

问：有三个来源就说明回答完整吗？答：来源数量不等于覆盖度，可能三段都没有关键条件。

问：离线摘录为什么不是自然语言总结？答：它刻意避免生成新结论，让你单独观察检索是否找对。
