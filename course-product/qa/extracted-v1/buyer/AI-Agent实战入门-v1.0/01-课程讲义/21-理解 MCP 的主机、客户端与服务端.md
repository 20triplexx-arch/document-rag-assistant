# 第21课 理解 MCP 的主机、客户端与服务端

模块：MCP 与协作 | 建议用时：阅读25分钟 + 动手20分钟

## 学习目标

辨认 MCP 的三个参与者和三类能力；区分协议、工具实现和模型决策。

## 中文讲解

MCP 提供应用连接外部能力的共同约定。Host 是承载 AI 应用的主程序，Client 管理与某个服务端的连接，Server 提供工具、资源或提示模板。模型仍由应用调用；MCP 不会替你训练模型，也不决定任务应该使用哪项能力。

工具用于执行动作，例如查数据库；资源用于提供上下文，例如表结构；提示模板提供可复用的任务表达。三者职责不同。外部能力接入以后，应用仍要判断任务相关性、输入是否有效和用户是否授权。

从使用角度看，先发现能力，再读取声明，最后调用具体工具。不能只猜一个工具名字并传参数。协议版本会变化，当前官方文档与旧案例 SDK 的握手方式可能不同；本课程讲稳定的角色与调用分工，具体连接命令以案例固定版本为学习对象。

> 流程：Host → Client → Server；Server 提供 tools、resources、prompts

本包没有可运行的 MCP 服务，三项基础练习也不是 MCP 协议实现。它们先帮你理解函数契约、状态和证据，然后再通过两个 MCP 案例观察框架如何把这些能力接起来。

## 示例与观察

把三个对象对应到浏览器案例：

| 角色 | 案例中的对应物 |
| --- | --- |
| Host | Streamlit 应用与 Agent 编排 |
| Client | 框架维护的连接与工具调用 |
| Server | 名为 playwright 的浏览器工具服务 |

服务名称来自配置，并不是 Python 函数本身。

## 动手任务

给“查询资料库”和“创建日历事件”各写出 Server 应提供的能力，说明哪个属于有副作用的工具。

## 参考答案

查询资料库是只读工具或资源读取；创建事件是写入工具，需要明确日期、时区、对象和授权。MCP 让连接统一，不会自动消除写入风险。

## 常见问题

问：MCP 就是 Agent 吗？答：它是协议；使用 MCP 的应用可以是 Agent，也可以是固定工作流。

问：本包有完整 MCP 部署课吗？答：主线讲机制，案例手册提供固定版本阅读与复现路线，未将上游服务验收为可直接使用的成品。
