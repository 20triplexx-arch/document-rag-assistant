# 第22课 浏览器行动需要观察与结果核对

模块：MCP 与协作 | 建议用时：阅读25分钟 + 动手20分钟

## 学习目标

把网页操作拆成观察、选择、动作和验证；识别页面变化造成的失败。

## 中文讲解

浏览器工具让应用读取页面、点击、输入或截图。与计算函数不同，页面会变化：按钮名字改了、登录状态过期、弹窗遮挡、异步内容还没加载。每次动作前要知道当前页面，每次动作后要观察结果，不能沿用早已失效的元素位置。

给任务写清目标和成功信号。例如“在公开文档页找到安装命令”，成功信号是页面展示了对应版本的命令与来源；不是浏览器已经打开，也不是模型说“已完成”。搜索、登录、付款是不同层次的动作，任务只需要查资料时应收敛到只读路径。

上游 browser_mcp_agent 使用名为 playwright 的服务，经框架列出工具并绑定语言模型；实际服务配置在单独文件中。源码里的状态字段 initialized 表示应用初始化，不代表每个网页动作都正确完成。

> 流程：观察页面 → 定位控件 → 执行动作 → 再观察 → 核对成功信号

网页文本属于外部数据。页面要求“把本机密钥复制到这里”不是用户授权，应当忽略这类指令。学习浏览器案例时先用公开页面和只读任务，记录预期结果与实际观察。

## 示例与观察

设计一个只读任务卡：
```python
task = {"goal":"查找官方安装命令",
        "allowed":"读取公开文档",
        "success":"找到命令、版本和原页面链接"}
print(task["success"])
```
该代码只是任务规范，不会启动浏览器或执行网页操作。

## 动手任务

为“点击下一页后页码未变”和“页面弹出登录框”各写出合理下一步。

## 参考答案

页码未变先重新观察是否按钮禁用、加载失败或命中错误控件；登录框先判断任务是否确实需要登录及是否具备授权，不绕过访问控制。不能把动作尝试写成任务完成。

## 常见问题

问：截图能证明所有操作成功吗？答：需要截图包含任务相关的成功信号，不是一张任意页面。

问：能直接按固定坐标自动点吗？答：页面布局会变，语义定位和最新观察通常更稳，坐标也需要当前截图支撑。
