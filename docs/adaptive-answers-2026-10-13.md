# 回答篇幅与表达调整

日期：2026-10-13。用户反馈所有问题都返回长文，套话和重复太多。

## 当前行为

默认讲解重点改为“自动篇幅”，API 与 CLI 一致。取消“复杂问题通常 6～14 个要点、1800～4000 字”的固定要求；输入 10000 字符、输出 8192 tokens、最多 20 条声明仍是容量上限，不是写作目标。

本地规则给出篇幅建议：简答约 160 字内、定义 260 字内、一般问题 500 字内、比较 650 字内、步骤 800 字内；明确深入时约 1400 字内。它们是软上限，没有最低字数、没有强制章节，多个必要子问题允许适当超出。用户“一句话”“100 字以内”等要求优先于所选讲解重点，背景长短不会直接决定回答长短。不另调用模型分类，也不机械截断已经生成的事实。

提示词要求第一句直接回答，每句话增加事实、原因、操作、条件或例子；删除寒暄、宣传词、重复提纲/结尾总结。同一事实只选择一份清楚的依据，不按教材重复讲。通常不加小标题；比较和操作分别采用要点与编号步骤。引用必须支持对应对象，不能把框架能力直接套成 RAG/Memory 等机制的定义或选型规则。资料缺口集中说明，保留拒绝无依据讲解的行为。

原文依据在生成回答后集中折叠；点击正文引用会展开本轮对应原文，并显示该条声明的摘录。原文模式和生成失败仍直接列出可读依据。所有文本继续使用安全 DOM 渲染。旧回答没有 `format` 时按原自然段方式显示；没有“自动篇幅”能力的旧服务回退原讲解选项。

`PROMPT_VERSION=evidence-adaptive-v4`，`RESPONSE_POLICY_VERSION=adaptive-answer-v1`。新增 `response_plan` 元数据，不保存额外私人讨论。请求去重保留升级前未显式指定讲解风格的旧记录复用，避免默认变化导致重复调用。修复同时间戳的历史记录排序，使用插入顺序决定先后，无数据库迁移。

## 验证与实际结果

- 离线检查：155 项后端、29 项前端、依赖、语法、216 篇/4220 个片段完整性和 40 题静态标注校验通过。未修改检索算法、题集或教材快照，未运行保留题；不把写作调整当作检索覆盖率提升。
- 实际 Flash 请求共 4 次，全部为公开教材问题，无裁判调用、重试或私人账号库写入。前三次有效回答均没有小标题：一句话解释 RAG 为 71 字/1 条；RAG 与 Memory 比较为 216 字/4 条，另有 130 字缺口说明，可见正文共 346 字（部分回答）；工具调用为 562 字/5 步。最终篇幅规则将缺口说明一并计入正文建议。第四次复用先前公开 Tool Call / Tool Result 检索包，响应格式未通过校验，未展示生成正文；旧样本为 672 字/5 条，因此没有可用的同题前后字数对照。
- 人工阅读发现比较回答仍有重复，并把框架能力套到机制选择上。随后补紧对象一致、差异去重和 JSON 合法值要求；最终规则通过离线回归，本轮不再追加真实模型调用。上述三条有效样本来自补紧前规则，不能视为最终规则或全题答案质量的验收。
- 完整公开结果保存在本机 `output/adaptive-answer-smoke-2026-10-13.json`，运行输出不提交。界面以临时账号库和已有公开样本检查，界面操作不增加真实调用。
- 桌面 1280×900 与手机 390×844 均无横向溢出，原文默认折叠；手机点击 E2 后展开本轮原文、显示对应摘录，焦点落在证据标题。截图位于本机 `output/adaptive-answer-desktop.png`、`output/adaptive-answer-mobile-reference.png`。Impeccable 检测器运行一次，仍报告旧目录关闭按钮被识别成图标卡片、旧“新讨论”颜色漂移；均未属于此次新增内容，没有改动原有视觉风格。
- 讲解任务和实验任务均为 0 后重启本机服务；首页 HTTP 200，`/api/library` 返回 `adaptive_answers=true`、216 篇资料和原有两种型号。

引文检查仍只验证逐字出处，`support_verified` 保持 false。模型仍可能忽略篇幅建议或错误解释，失败会拦截；需要后续人工内容评测，不能用本轮字数变化宣称答案正确率提升。
