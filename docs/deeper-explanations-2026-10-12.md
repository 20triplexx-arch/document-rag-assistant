# 讲解深度与容量调整 · 2026-10-12

用户反馈现有回答简单、片面，输入和输出容量不足。本轮扩大内容容量，调整教学提示词和取证，保留本机运行、账号隔离、调用额度与引文检查。真实模型调用为 0；实际生成内容的深度及事实支持尚未做真实模型验收。

## 原因与实现

原版同时限制了输入、生成预算、声明数量和声明长度，还要求“用简洁中文讲解”。固定题集也证明有些问题优先召回贡献邀请、学习目标或安装说明。

| 项目 | 原值 | 新值 |
| --- | --- | --- |
| Web/CLI 问题长度 | 500 字符 | 10000 字符 |
| Web 请求体检查 | 16 KiB | 128 KiB |
| 模型输出预算 | 1400 tokens | 8192 tokens |
| 回答要点上限 | 4 条 | 20 条 |
| 单要点正文 | 500 字符 | 1600 字符 |
| 单条连续引用 | 350 字符 | 800 字符 |
| 缺失信息说明 | 500 字符 | 2000 字符 |
| SDK 请求超时 | 45 秒 | 120 秒 |
| 并发任务租期 | 180 秒 | 360 秒 |
| 单条证据范围 | 原始片段至多 1400 字符 | 同一标题段补邻接正文，至多 3200 字符 |

统一边界位于 `study_rag/limits.py`。前端按 Unicode 字符计数；HTML 的 UTF-16 `maxlength` 为 20000，为 10000 个含代理对的字符留足空间，逻辑提交和后端仍限制 10000 字符。超过限制时保留输入、显示提示，不发请求；新讨论标题按 Unicode 字符截取，避免截断 emoji。

提示词升级为 `evidence-depth-v2`：先回答核心问题，再按需解释概念区别、工作机制和因果关系、输入输出/状态变化、实现步骤、具体例子、选择条件、失败模式和边界。复杂问题通常要求 6～14 个有证据的要点、约 1800～4000 字的讲解；简单问题可以更短，资料不足时说明缺口，不凑字数。输出预算包括 JSON 与引用，8192 tokens 不等于保证输出 8192 字。

每个要点新增可选 `heading`，旧回答没有该字段仍可显示。正文支持自然段和分行步骤；相邻同标题只显示一个分节标题。引用摘录默认折叠，原文编号仍定位本轮依据。较长的问题折叠显示完整背景，完整输入仍保存。编辑器随输入增长，桌面和手机均保留滚动上限，避免长期占据阅读空间。

较长讲解可能增加等待时间与 token 用量。日调用次数和一题最多一次模型请求保持原约束，没有自动重试。长生成的并发租期延长，完成或失败仍立即释放任务槽。达到输出上限时不展示未完成 JSON，记录使用量并明确提示原因；这是针对官方 [Chat Completions 的长度结束状态](https://api-docs.deepseek.com/api/create-chat-completion/) 的处理，不代表已实测当前账号的服务响应。

## 取证改进

检索器升级为 `balanced-prose-bm25-v4`：

- 根据问题意图区分教学正文、学习目标、贡献说明、安装/环境步骤。概念问题排除后面三类；确实问安装、课程目标或贡献时保留相应资料，并给予意图匹配权重。
- 增加安装/启动/依赖的中英术语对应，让真正询问安装步骤的问题能找回英文正文。
- 只在同一来源、同一标题段内补相邻片段，保留原文半开字符区间、行号及固定版本链接；补充范围不跨标题，代码/MDX 遮罩仍在完整原文上应用。
- 两个候选扩展后高度重叠时不重复占据证据名额。每集合最多 2 条、全部最多 8 条的边界保持原约束。

`chunk_id`/`anchor_chunk_id` 指向检索锚点；扩展后的原文请按报告的 `start_char/end_char` 或行号链接回查，CLI 按片段 ID 读取的是锚点片段。索引和原文没有重新构建或替换，仍为 216 篇、4220 个片段。
