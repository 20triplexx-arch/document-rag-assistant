# 从功能原型到完整学习流程

日期：2026-10-14（Asia/Shanghai）。用户反馈各项功能不够精，并确认同时需要：问答能教会人、案例能跟着做、学习有路线和复习。

## 判断与证据

现有项目已有账号隔离、固定来源、原文位置、配额和离线评测基础，但学习产品的主要能力尚未验收。增加模型选择、输入容量或收紧文风只能解决局部问题，不能证明学习者理解了内容或能完成实践。

本轮阅读核心代码、来源配置、既有真实试答和开发题报告；执行四次公开问题的离线检索以及上下文复现。没有读取私人讨论、调用真实模型、运行案例、修改教材快照或固定题集。

| 能力 | 当前证据 | 用户实际遇到的缺口 |
| --- | --- | --- |
| 找到支持答案的资料 | 2026-10-13 开发题覆盖 26/49 个必要要点，25 道可回答题仅 9 道完整覆盖；82/100 条证据未标注判定 | 相关词命中不代表找到答案，不能拿未判定比例当错误率 |
| 口语理解 | 本轮“记住上周聊过的内容”召回记忆正文，也夹入框架介绍、资源导航、安全清单和宝可梦说明 | 用户不会按教材标题提问，检索容易围绕几个词发散 |

## 三项要求用同一条学习流程承接

**学习目标 → 少量必要概念 → 有依据的问答 → 一个可理解的案例 → 一次可检查的练习 → 记录掌握证据 → 回到下一目标或复习。**

首页继续允许直接提问。学习路线、相关案例和练习使用同一主题与讨论语境，避免让用户在互不关联的入口间自己拼学习计划。保留白色简洁工具布局、模型选择和只查原文，设置按需要展开。

先在一个主题做完整流程的样板，再扩展主题。建议先用工具调用：概念与输入输出明确，可以设计不需要模型密钥的模拟函数练习；同时用 RAG/Memory 比较、口语记忆和明确换主题问题检验问答，避免只在样板主题上表现好。本节为后续改造范围，尚未实现。

### 问答达到的标准

- 答当前问题，先给直接结论，必要时才补机制、条件或例子；篇幅由问题决定，不能给所有问题套固定教学提纲。
- 一个结论需要多份资料时能够绑定多份依据。当前“一条声明只对应一个引文”的结构需重新评估，避免跨来源比较被切成重复小段。
- 分开处理正文和章节元数据；按问题需要分配有限证据，兼顾多概念覆盖、重复和弱匹配，不靠每套教材轮流取一条凑齐来源。
- 两个对象缺一方的支持资料时，给出能支持的部分并明确具体缺口；不凭共现、框架名字或概念名称推导选型规则。
- 资料不足、格式失败、引文失败和服务失败能定位原因、保留可读依据；失败不绕过校验、不额外自动调用。
- 定义、比较、操作、反例和代码说明分别用适合的表达；代码与表格能够正常阅读，资料依据与正文分层。

### 案例达到的标准

- 每个教学案例给出学习目标、前置知识、输入输出、关键实现路径、常见失败以及完成判断，不把仓库简介当完整教程。
- 按固定提交导入必要实现文件，建立函数或代码段到原文件行号的对应。代码只做静态解析和阅读，不在服务器执行第三方代码或自动安装课程框架。
- 概念检索与代码检索采用不同的正文处理规则。案例只有 README 时明确能力范围；能够定位代码后才回答具体参数校验、错误处理和调用关系。
- 新实现文件放入独立快照；原来源 ID、提交和字节保持一致，旧快照与旧评测仍可复现。涉及语料版本改变的题集以新版本处理，不覆盖旧基线。
- 首个练习优先用本地模拟输入，给出可观察的结果和检查条件。运行外部模型或付费服务的步骤注明依赖与费用边界，实际运行不能假装已经验证。

### 学习组织达到的标准

- 按知识先后安排路线，解释每个目标为何放在此处，而不只是把教材章节排成菜单。
- 一个主题关联概念问答、原文、案例与练习。用户能明确继续上次学习的位置，进入该主题时获得当前目标和下一步。
- 进度按账号独立保存，区分读过、练习完成和有检查依据的掌握。点击完成或答对一次不等于掌握。
- 复习根据已学习内容和练习中的缺口组织，保留用户对记录的控制；没有订阅时不额外发送提醒。
- 练习参考答案和评分依据要版本化、能回查原文。自动点评只作辅助，未复核的题或评分不能显示为已验收。

## 分批改造与验收

| 顺序 | 完整交付范围 | 验收证据 |
| --- | --- | --- |
| 1：回答能用 | 修复话题串线，改善多概念取证与口语问题，建立真实回答内容复核和失败定位 | 使用既有开发题与公开用户场景；保持来源位置正确；逐条检查关键事实、引用支持、必要要点、重复与缺口。检索基线不得倒退，不能靠改答案标准提分 |
| 2：一个主题教会 | 将一个主题的概念、问答、必要实现代码和练习打通 | 没有读过仓库的学习者能说明输入输出并完成模拟练习；每个关键实现说明可定位代码，失败例也能检查 |
| 3：连续学习 | 主题路线、账号独立进度、练习记录与复习 | 换讨论、重新登录后能继续；用户记录隔离；状态准确区分阅读和掌握；不能以勾选次数生成虚构成绩 |
| 4：扩展主题和体验收尾 | 复制已通过的流程，优化阅读、设置与失败恢复 | 逐主题人工验收；桌面/手机、键盘、长内容和失败流程验证；保持账号、教材和调用约束 |

每批报告都分别回答“功能能否运行”“资料是否支持答案”“用户能否完成学习任务”。代码测试数、语料篇数、输出字数与模型型号均不能替代后两项。保留题只用于显式阶段验收，日常调参使用开发题。

## 本轮已完成的确定性修复

- 独立问题与显式换话题不再携带旧回答摘要；收窄中文追问识别，`详细介绍MCP`、`再解释一下MCP是什么`、`这个MCP协议如何连接服务器`、`这个项目怎样安装`不再继承旧 RAG 主题。`这个怎么实现`、`继续讲`、`举个例子`保留本讨论追问。该识别仍是规则方法，不宣称能理解所有指代。
- `CONTEXT_VERSION=referenced-chat-context-v2`。问题长度、四轮/6000 字符边界、所有权与资料范围隔离、历史非事实证据的规则保持不变。
- 生成请求附带从实际 Pydantic 类型生成的 `ANSWER_SCHEMA`，减少提示词与本地字段、枚举、长度约束漂移。`PROMPT_VERSION=evidence-adaptive-schema-v5`，不增加模型调用。
- 格式失败记录 `response_schema` 与安全字段路径/错误类别，逐字引文失败记录 `quote_source`。不保存校验错误里的输入、正文、消息或上下文；不重试、不降低引文要求。它改进定位，尚未证明真实生成失败率降低。
- `verify.ps1`：159 项后端、29 项前端、依赖/语法、216 篇/4220 片段和 40 题静态校验通过。检索算法、固定题集、账号与教材未修改；本轮真实模型调用为 0。
- 服务检查发现当时 8765 未监听；确认讲解/实验任务均为 0 后已启动当前服务。首页 HTTP 200，资料仍为 216 篇，模型选择与自动篇幅保持可用。账号与讨论没有重置。

三块能力的完整重做尚未完成。本轮交付的是核对后的质量诊断、明确的改造范围、验收标准和上述基础修复。
