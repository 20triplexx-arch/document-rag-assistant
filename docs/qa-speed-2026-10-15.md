# 问答质量与响应速度：实现及验收

2026-10-15（Asia/Shanghai）。**共享提速和逐段显示已实现；v3 候选未通过内容验收，保留原默认语料与回答协议。**

## 已应用的能力

- 原文、Git blob、目录和 SQLite 索引每次仍核对；只缓存精确字节及来源元数据确定的分块、正文资格、分词和检索统计。缓存后改动原文或索引仍拒绝使用。
- 请求只核对一次语料；单集合筛选与 v3 分派共用本次核对结果。旧检索先排序再展开证据，正文资格与词频长度也在已校验材料中预计算。
- DeepSeek 客户端随应用生命周期复用连接、关闭时释放；仍关闭思考模式、最多一次生成、不重试、不切换服务商。
- `POST /api/ask/stream` 与原 `/api/ask` 共用身份、所有权、CSRF、输入、模型、资料范围、请求去重、配额与保存逻辑。请求字段不变，新增接口返回 SSE JSON 事件：`progress`、`evidence`、`block`、`result`，工作线程异常返回固定 `error`，不泄漏异常正文。
- `block` 只包含通过本轮结构、连续引文及源码核对的完整单元。JSON 转义、中文和嵌套结构可跨网络分片；最终完整校验失败时前端撤回预览，展示依据、失败说明并保留输入。
- HTTP 断线不取消已预留任务：后台继续校验、保存并结算一次。刷新本人讨论可读取结果；相同请求编号不会再调用模型。没有自动重连或失败后改走非流式调用。
- 响应新增 `timings`，记录检索、生成、首次内容、首次已校验块、校验和服务端处理耗时；真实报告另记录 HTTP 客户端总耗时。服务端 total 在保存记录前采样，客户端总耗时覆盖保存和响应传输。
- `/api/library.streaming_answers=true` 宣告流式能力。旧服务不含该字段时页面继续使用原接口；原文模式零模型调用。现有 v1 claims 和 v2 blocks、旧讨论继续读取。

## 候选能力与失败修复

v3 候选按子问题和主题建立候选通道，必要面优先选取，MCP 权重仅作用于协议聚焦的问题；不会把含其他必要主题的问题全部压向 MCP。简答至多三条，复杂问题至多八条，正文与源码、指定版本规则保留。

生成使用独立的片段编号契约，公开结果仍为严格 v2：后端将本轮 `evidence_id/span_id` 映射为连续原文及位置，再执行原有校验。未知编号不猜测、不纠正。原文代码可通过连续的 `code_reference` 选择恢复，保留短结构行、空白与缩进；教学示意仍明确区分。

开发试答发现三个模型输出在 list/table 父块重复带 references。最终生成契约允许这种重复汇总，但必须完全来自子项已有引用；后端仅去掉可证明冗余的汇总，公开 v2 校验仍严格拒绝其他多余字段、无依据引用和缺失子项引用。没有丢弃未知引用、补造内容或增加修复调用。

## 速度结果

同机、同八个公开问题、每题预热后测三次；没有调用模型。旧路径使用改动前保存的源码包，当前默认仍使用相同 216 篇 / 4220 片段：

| 当前默认检索 | 改动前 | 改动后 |
| --- | ---: | ---: |
| 中位耗时 | 896 ms | 252 ms |
| P95 | 923 ms | 266 ms |

这组问题的所有选中文档与原文起止位置逐项一致。完整采样保存在 `output/qa-speed-20261015-v1/shared-performance.json`。这是检索耗时，不是完整回答速度或长期 SLA。

候选预热检索 P95 为 **356 ms**。开发题必要支持覆盖保持新题 **70/72**、旧题 **35/49，17 道完整覆盖**；工具主题仍只有 7/9，检索覆盖不能当作生成正确率。

最终八题中七个结构/出处有效样本，首次已校验块中位 **1.60 秒**，完整 HTTP 响应中位 **3.64 秒**。首次冷请求为 7.71 秒、首段 5.82 秒，不能隐藏冷启动代价；另有一题校验失败，已单列。

原四个基线预留中，一次受限网络连接中断，保留为失败占用且没有重试，因此只得到三个 HTTP 基线。三组同题开发测速中，只有一组前后均产生有效回答；开发提示为 v2，最终验收为 v2.1 且题目不同。**不能据此宣称最终版完整回答提速 25% 已通过验收。**

## 内容验收与预算

冻结八题结构/出处 **7/8** 有效，严格 AI 内容复核仅 **2/8** 通过；不是人工正确率。逐题原文链接和说明见 [内容复核](../reviews/qa-speed-2026-10-15.md)。主要问题：

- 工具题仍从函数过滤推导框架校验责任，且错误描述字面表达式 `1` 的路径。
- RAG 题把本地函数说成库导入，并对未收录库内部是否重新检索/复用作过强断言。
- MCP 题输出不存在的 `span_id="5"`，被严格拦截；必要的 `server/discover` 支持也没有召回。
- 记忆题对后台延迟取舍取证不足；规划题重复，多 Agent 题混用通用模式与 Deep Agents 特有配置。

本轮独立账本 `output/qa-speed-20261015-v1/budget.sqlite3`：**20 次已预留，729,223 tokens 保守预留**，低于 100 万；供应商报告输入 120,926、输出 12,509 tokens。分配为 4 基线 / 8 开发 / 8 验收，其中一次网络中断，19 次有模型返回。结构失败仍计数，没有自动重试或付费裁判。**本轮额度已用尽，不得清账、换账本重跑或通过维护入口绕过上限。**

真实请求通过本机 Uvicorn、认证 HTTP 接口和真实检索执行，没有替换检索。发送前检查冻结问题、空历史和白名单公开 GitHub 原文；仅使用实验账号库，不读取正式讨论。新场景复用了既有原文标注与概念，不是独立人工基准。基线保留源码快照；开发/验收早期保存了代码哈希、实际输入和原始输出，未保存每个中间实现版本，不能声称所有历史阶段均可直接复现。

最终验收后仅进一步预计算旧语料路径的正文资格与词频长度，v3 生成及选择逻辑未再调整；旧路径原文位置对照通过，没有追加生成。
