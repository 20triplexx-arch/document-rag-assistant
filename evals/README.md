## 运行

在项目根目录执行：

```powershell
# 日常调参默认只跑 30 道开发题
.\.venv\Scripts\python.exe starter.py evaluate --split dev
# 发布候选或建立基线时显式运行全部 40 题
.\.venv\Scripts\python.exe starter.py evaluate --split all
# 只核对题集和语料，不执行 40 次检索
.\.venv\Scripts\python.exe starter.py evaluate --check-only
```

不传 `--split` 时使用 `dev`。`holdout` 可显式选择，但日常调参不运行、阅读或据此修改算法。`--check-only` 总是校验全部标注，终端和记录只展示数量、版本等元数据。

支持既有全局参数，也支持放在 `evaluate` 之后：

```powershell
.\.venv\Scripts\python.exe starter.py --data-dir .\data\courses-cases-20261010-v1 --output-dir .\output evaluate --split dev
.\.venv\Scripts\python.exe starter.py evaluate --dataset .\evals\agent-learning-v1.json --data-dir .\data\courses-cases-20261010-v1 --output-dir .\output
```

逐题 JSON 写到 `output/evaluate_<随机编号>.json`。终端只展示摘要。开发题结果只包含开发题正文、标注和证据；全量报告额外含保留题，应避免在调参期间阅读保留题明细。题集与可提交摘要位于 `evals/`；输出目录已被 Git 忽略。完整检索评测独立运行，`verify.ps1` 只接入静态校验。

## 数据与标注契约

[agent-learning-v1.json](agent-learning-v1.json) 包含 40 题：20 道单集合题（每集合 4 题）、8 道跨集合比较、6 道口语/中英术语改写、6 道资料不足题。其中 30 道开发题、10 道保留题；按具体学习目标分组，原题与相关改写不能跨划分。保留题覆盖五个资料集合。

当前交付版本为 **agent-learning-v1.1**。它固定到 216 篇原文、初始 4220 个片段的语料：

```text
corpus_version: 14830ef070b791490d7b73b177d94101931ed372d3f0eb58f38907f15947bcb2
dataset_sha256: 8330baaf7bebdd53af1d6c1004d56d9e705a0aad666fd6bee02c3e4793cb36c6
```

仓库通过 `.gitattributes` 保留冻结题集文件的原始字节与换行，避免 Git 自动换行转换改变上述哈希；编辑器也不应仅为格式化改写该文件。

标注在查看本轮逐题检索排名前人工阅读固定原文选取。每道题记录学习目标分组、范围、可回答程度、必要答案要点、缺失信息和已知干扰。每个要点可有多个**等价的替代**支持段落；命中任意一个即可覆盖该要点。需要多个事实共同支持时拆成多个要点，不能把其中一个事实误写成另一事实的替代。

每个段落以 `source_id`、`start_char`、`end_char`、`quote`、`start_line`、`end_line` 和理由定位。字符区间为 Python Unicode 字符的半开区间 `[start_char, end_char)`；行号从 1 开始、两端包含。位置对应 `core.validate_text` 解码并统一换行后的原文，原始文件字节另由现有 SHA-256/Git blob 契约核对。标注不以片段 ID 为依据。

静态校验检查数量、题型、唯一题号/题面、30/10 划分、组间隔离、单集合每套四题、跨集合每个必要来源、支持与干扰的逐字摘录/位置/行号、资料不足检查范围及缺失依据。来源、原文或语料版本不符时返回非零退出码。`baseline_chunks` 保存初始分块数量，评分仍依据原文位置：未来在**同一原文版本**重建索引/调整分块可重新评测，报告记录实际片段数和索引契约；替换原文必须重新标注并升级题集。

## 评分

每题调用 `study_rag.rag.retrieve(..., per_book=2)`，每集合最多两条、五个集合合计最多八条。检索器及排序保持现状。支持命中同时要求：

1. 返回证据来自标注的来源。
2. 返回证据的原文区间完整包含标注段落；只覆盖一部分不计入。
3. 摘录通过同一代码/MDX 遮罩检查，并确实出现在 `context_text`，使用现有引文空白、HTML 标签与强调符号正规化规则比较。

代码或组件属性里的文字即使原文和关键词匹配也不能计为概念支持。相同来源和起止位置的重复证据保留排名记录，但不重复增加证据分母或要点覆盖；不同证据支持同一要点也只计一次。

摘要报告：

| 指标 | 分子 / 分母 |
| --- | --- |
| 支持要点覆盖率 | 已覆盖要点 / 完全可回答题的必要要点 |
| 完整覆盖题数 | 全部必要要点命中的完全可回答题数 / 完全可回答题数 |
| 至少一个支持要点题数 | 命中至少一个要点的完全可回答题数 / 完全可回答题数 |
| 已标注干扰证据比例 | 命中已标注干扰段落的证据 / 全部去重证据 |
| 未判定证据比例 | 没有命中支持或干扰标注的证据 / 全部去重证据 |

一个证据可同时含支持与干扰，分类为 `support_and_distractor`，也计入干扰比例。未标注内容保持 `unjudged`；既不能自动算错，也不能当作已验证支持。原文链接和详细正文保留在报告，方便后续人工审查。

6 道资料不足题包括 3 道部分可回答、3 道无充分资料。它们不进入完整支持统计；报告单独列出已知要点覆盖、缺失事实、检查范围/依据和干扰召回。没有命中不证明资料不存在；缺失标签基于固定来源范围和收录边界。这里没有生成答案，不能据此声称模型能够拒答。

结果还记录题集哈希、原文版本、实际片段数/分块契约、检索器与评分器版本、各证据原始排名和检索分、原文链接、匹配要点、判定及逐题耗时。指标没有虚构的达标阈值。
