# DeepSeek 初次试答复核（2026-10-09）

结果：接通模型与执行链路，不通过内容质量验收。不要将本记录标成项目完成或两本教材课程全部完成。

仅固定的 awesome Stage 6 与 Hello 第八章；89 个片段。语料版本 `55b01a52efdadb5bb277aed73232d329cff54024dd86265c91aaad59ff1bb0f4`。模型 `deepseek-flash`，密钥只读现有服务端环境变量，官方接口；没有 Embedding 调用。

## 第一次失败

JSON/引文校验未通过，`answer=null`、`quote_verified=false`。原始模型草稿未保存，无法逐项追溯究竟哪条引文失败，不能断言具体原因。之后合成测试发现并修复了 HTML 强调标签与正文投影匹配问题；它能证明修复此类边界，但不能反推第一次一定因此失败。

## 第二次人工复核

程序仅证明四条引文属于本轮证据，始终 `support_verified=false`。人工复核另发现：

1. 对人类记忆分类的解释引用的片段，只描述长期记忆存储时长，未完整支持整条分类结论。
2. 对记忆编码、存储等过程的解释，所选引文仅概括模块划分，没有完整包含过程依据。
3. awesome 的 Agent Memory 适用场景解释与其引用大体一致；仍需固定标准逐项评估，不单独宣布整题成功。
4. 关于 RAG 获取外部证据、Memory 读回状态的解释，绑定了 E4 自测清单。引文“我能说出 Retrieval、RAG 与 Memory 各自做什么。”只是一条学习目标，不支持该解释。相关依据在 E2，不在所选 E4。

缺失说明还将“本轮证据不够”写成“两本教材都没有直接给出完整对照定义”，超出了检索能证明的范围。此次讲解不算正确回答，符合用户此前确定的标准：“真实引用但不支持结论，不算正确。”

## 已改与待验证

已加强单要点、完整引用支持和检索范围限制的提示词；保留代码/HTML 清洗、分书取证和出处核对。改提示词后没有新增真实调用，因此没有改进效果结论。

下一步先固定开发题/保留题及逐条依据，分开统计检索命中、引文出处和语义支持；针对错误引用评估证据选择/重排，必要时对照一次有预算的审阅调用。资料不足须另做真实测试。不能仅增加模型调用或更换模型就宣称质量通过。
